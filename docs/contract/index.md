# The contract

The four MeshBee components ship independently. What keeps them interoperable is this contract:
the MQTT payload format and the HTTP API. It is deliberately **small, explicit, and versioned**.

This site is its **single home**. The artifacts below live at stable URLs that other repos can
link to. Release notes should point here rather than paste a copy — a duplicated spec is a spec
that goes stale without anyone noticing.

!!! note "English only, by design"

    Contract pages are not translated. They describe machine-facing specs and schemas, where a
    second wording is a second source of truth waiting to disagree with the first.

## How the artifacts stay current

**The OpenAPI spec is generated, never hand-written, and never copied here.** It lives at
`api/openapi.json` in [`meshbee-server`](https://github.com/fablab-imperia/meshbee-server), where
`make openapi` regenerates it. The [API reference](api.md) page fetches that file directly from the
repository's `main` branch when your browser loads the page.

There is deliberately **no copy in this repository**. A duplicated spec is a spec that goes stale
without anyone noticing, and the whole point of publishing one home for the contract is that there
is only one file to be right. The cost is that the reference tracks `main`, including changes that
have not been released yet — read the [compatibility matrix](compatibility.md) when you need to
know what a given release actually speaks.

**The MQTT payload schema is different** — `meshbee-server` does not generate one, so it is written
and kept in step by hand in this repository and published at the stable URL above. When an exporter
exists upstream, it moves to the same arrangement as the OpenAPI spec.

## What is not versioned yet

The pages here describe the interface as it ships today. Two parts of the intended versioning
scheme are **not implemented**: the MQTT payload carries no version integer, and the HTTP API is
served under `/api/…` with no version segment in the path. Both are documented as design intent on
the [MQTT payload](mqtt-payload.md) page and in [Architecture](../architecture.md), and clearly
marked as such. The compatibility matrix is real and maintained.
